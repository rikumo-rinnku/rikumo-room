# 服务器往返试麦（已撤回）

2026-10-05：用户要求移除试麦，前端连接逻辑和后端接口已删除。下文仅作为历史设计记录，不代表当前可用功能。

## 声音路径

麦克风 → 当前浏览器原生处理和输入音量 → Opus 编码 → 上传 LiveKit → SFU 转发 → 本机另一个只接收的连接 → 解码 → 当前收听音量和输出设备。

不在本地直接回放麦克风，不经 Python 转码，也不录音。发送、接收使用同一媒体服务器的独立临时房间，其他用户无法通过普通房间入口加入。临时房间不写入业务房间表，不影响大厅人数。

这是本机网络的一次上传及下载，可验证编解码、服务器转发和本机接收后的声音；不能完全复制其他用户的网络、缓冲、音量和扬声器听感，也不能用听到的回声间隔直接当作单向语音延迟。

## 操作

- 在通话底部左侧“音频设置”中开始/停止试麦。
- 先静音并撤下普通房间的音频发布，保留同一条采集和处理器；移到试麦发送连接。此前没有麦克风音轨时才创建一条，同一时刻仅一条采集。
- 听到的是服务器转发后下载的音频。普通房间仍保持连接、可继续听其他成员；试麦发送不会进入普通房间。
- 支持调节输入及收听音量；遵守收听开关。试麦期间锁定设备切换和普通房间开麦。
- 结束后先静音、撤下试麦发布、断开试麦连接，再以静音状态回到原房间发布；用户自行开麦。
- 开始试麦前必须先关闭并撤下普通房间发言，再请求试麦接口。接口缺失或请求失败时仍保持真实静音，结束按钮状态从 SDK 实际状态读取；保留启动失败原因，不能将失败统一显示成正常结束。
- 短暂重连显示恢复状态并交由 SDK 恢复；实际断开时结束试麦。诊断记录房间创建、普通房间撤下、试麦发送/接收连接、发布、返回音轨、失败及停止原因。
- 不设置试麦时长限制，由用户点击“停止试麦”手动结束；关闭音频设置、离房、切房、试麦断线或麦克风结束时停止并清理。浏览器阻止播放时提供“恢复试麦收听”。推荐佩戴耳机。
- 离房或注销时不恢复原房间音频，释放采集。

## 服务端

- `POST /api/mic-test`：要求有效登录且未处于访客待清理状态。创建随机临时房间，仅签发该房间的两个短期令牌；发送者只能发布麦克风，接收者不能发布，均不能发送业务数据。
- `DELETE /api/mic-test/{test_id}`：只能清理当前用户命名空间下的试麦房间。
- 房间最多 2 个参与者；无人加入超时 30 秒、全部离开后 10 秒清理。前端主动清理失败时由媒体服务清理空房间。令牌 2 分钟有效期限制重新加入，并不强制踢出已连接者，不是试麦时长限制。
- 日志以中文记录开始/结束，正常试麦日志默认隐藏，失败日志显示。无需数据库迁移或新依赖。

## 发布与验收

本功能涉及前后端，使用完整 `--update`，不要使用 `--web-only`。无需重启或重新配置 LiveKit。

前端类型检查与生产构建已通过；本地内置浏览器受测试证书信任限制，尚未完成真实麦克风试听及公网验证。请检查：开麦和静音状态开始试麦、返回声音、其他成员听不到试麦、停止后保持静音并能再次开麦、收听开关和音量、设备断开、取消连接及离房清理。
