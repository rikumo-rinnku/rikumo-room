# 降噪开关（2026-10-05）

音频设置包含“原生降噪”和“RNNoise 降噪”两个独立开关，无强度滑块。原生默认开启，RNNoise 默认关闭；当前浏览器使用 `rikumo-denoise-v1` 保存选择。不自动关闭另一种降噪；叠加处理可能改变人声，可由团队在通话中对比原生单独、RNNoise 单独与叠加效果。

## 采集和处理路径

同一物理麦克风 → 浏览器回声消除/原生降噪/自动增益 → 可选 RNNoise → 可选收音阈值 → 输入增益 → LiveKit 发布。普通通话使用一条采集和处理器，不增加麦克风采集或服务器音频转码。

原生开关使用 LiveKit `LocalAudioTrack.applyConstraints` 修改真实采集轨道，保留当前约束并读取 `getSourceTrackSettings()`；不对处理后的输出轨道应用约束，也不自动 restartTrack。没有活跃采集时先保存偏好，下次采集应用；解除静音时补应用尚未生效的偏好。浏览器未报告/未应用设置时展示明确状态；拒绝修改时保留原偏好并中文提示。

RNNoise 使用锁定依赖 `@shiguredo/rnnoise-wasm@2022.2.0` 的常规/SIMD WASM。本项目自有 AudioWorklet 桥接其导出 ABI（malloc/free、rnnoise_create/destroy/process_frame 等）；依赖升级必须重新核对 ABI。模型由主线程从同源静态资源加载及编译，再向工作线程传递 WebAssembly.Module；WASM 不访问外部服务。Apache 和 BSD 授权随网页发布至 `/licenses/`。

仅在 48 kHz 音频上下文启用 RNNoise，每帧 480 个采样，使用单声道和固定环形缓冲，按 16-bit PCM 幅度缩放输入并恢复浮点输出。额外帧拼接缓冲为 480 个采样（10 ms），算法自身及浏览器/编码/网络/播放延迟另计，不能把此数字当成最终附加延迟。优先建立 48 kHz 上下文；设备/浏览器拒绝时保留默认音频上下文，RNNoise 回退，普通通话可继续。

模型仅在开启时下载/编译，工作线程初始化确认成功后才切换处理路径。关闭时断开并释放降噪状态及端口，恢复剩余阈值/增益路径。开启/离房取消通过版本号处理；初始化限时、处理异常或非有限输出触发中文提示并回退。模块缓存可保留，但无活跃推理节点。主线程不循环搬运音频、不增加第二条采集。

## 当前结果及发布

类型检查、生产构建已通过，两个模型和工作线程为独立同源发布资源。未新增或运行测试，未部署公网；模型听感、游戏负载、长时间通话、后台标签页、静音/解除静音和设备切换均待真实设备验收，不能声称已经解决旧版电音。

RNNoise 本身仅需前端更新。2026-10-05 已撤回试麦，删除试麦后端接口的这一版须使用完整 `--update`；LiveKit 无需重启。出现电音时先关闭 RNNoise 作为对照，由发送和接收双方导出诊断记录；不要仅凭几秒试听判定稳定。
