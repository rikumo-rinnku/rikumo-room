# 可调收音阈值（2026-10-05）

## 使用

通话左侧“音频设置”中开启“收音阈值”，调节 -70 至 -10 dBFS，初值 -45，默认关闭。数值越高，越需要大声说话才会打开收音。可在团队通话中边说话边调整；不要将正常说话或轻声字尾挡掉。

面板打开且阈值已启用时显示输入电平和收音状态；关闭面板不关闭阈值，只停止电平通知。阈值关闭时没有额外测量节点，实时电平也停止。设置保存到当前浏览器独立的 `rikumo-threshold-v2`，不继承旧版电音回归版本的开关状态。

阈值只能在说话间隙阻断较小声音；风扇声在说话期间仍可能通过。检测的是浏览器原生处理和可选 RNNoise 之后，应用输入音量增益之前的信号。这里的 dBFS 不是现实环境的分贝值。

## 与旧版的区别

- 关闭：采集源直接连接原输入增益，断开并释放阈值 AudioWorklet、关闭消息端口。没有后台阈值计算；已加载模块可以留在当前 AudioContext 缓存，但没有活跃处理节点。
- 开启：按音频块计算 RMS，5 ms 平滑开门、4 dB 关闭滞回、180 ms 保持、60 ms 平滑关门。没有额外音频排队或重采样，不通过主线程定时器开关音频。
- 电平消息最多每秒 5 次，仅面板打开时发送；后台通话不更新电平界面。
- 不重新采集、不增加第二条麦克风、不更换已发布输出音轨。普通通话使用同一处理器及设置；试麦功能已于 2026-10-05 撤回。
- 关闭或销毁会取消未完成的启用操作；更换设备只替换采集源。处理节点加载失败或运行异常时关闭阈值并回到原路径，中文提示并记录诊断。
- 本文描述阈值实现；后续同日加入的原生降噪和 RNNoise 独立开关详见 audio-denoise.md。

本方案仍需要真实设备的长期通话确认，不能据此断言已彻底解决之前的电音问题。阈值开启会增加少量音频处理工作，开门/关门包络也会影响字头和字尾。

## 实施及发布

仅修改前端，未新增后端接口或依赖。阈值本身仅需前端更新；删除试麦接口的这一版须完整更新，详见 audio-denoise.md。

前端类型检查及生产构建已通过，阈值 worklet 独立输出为发布资源；未部署到公网。未新增或运行测试。长时间通话、游戏负载、后台标签页、开关阈值、静音/解除静音、切换设备均待用户确认。出现异常时关闭阈值，并由发送者及接收者标记、导出通话诊断。
