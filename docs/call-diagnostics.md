# 通话诊断（第一阶段）

## 使用

1. 进入语音房间，点击底部“通话诊断”。在设置页面也可打开。
2. 听到电音时点击“标记出现电音”。异常发送者和听到异常的接收者分别标记、导出，便于对照时间。
3. 点击“导出诊断”保存 JSON。退出房间后仍可从顶部入口导出最后的记录；刷新页面会清除记录。

## 记录范围

- 每 5 秒读取已发布/订阅音轨的浏览器 WebRTC 统计，保留最近 360 次采样（正常前台采样约 30 分钟）及最近 200 个事件。
- 每一路音频记录网络往返时间、抖动、丢包、码率；接收音轨额外记录丢包补偿采样比例。浏览器未提供的数据以空值和“—”表示。
- 接收丢包/码率/补偿使用相邻采样的累计计数差值。首次采样、计数重置、无有效数据时不显示区间指标；发送丢包来自远端接收报告的累计比例。
- 记录连接开始/成功/失败、重连、断开、麦克风开关、采集开始、处理器初始化/源替换/释放、设备切换和用户电音标记的时间。
- 保存浏览器版本、音频上下文状态、浏览器实际采集设置、设备名称及音量设置。音轨实际参数未提供时不假定降噪已生效。
- 记录仅在浏览器内存中保留，导出时生成本地文件。无后台上传接口，不记录音频内容、令牌、密码、设备 ID、候选网络地址或完整 RTC 报告。导出文件含成员名称和设备名称。

## 指标限制

网络往返时间（RTT）不是从说话到对方听见的完整延迟；不包括全部采集、编解码、缓冲与播放耗时。发送和接收路径也可能不同。

丢包补偿上升可帮助判断网络或音频流不连续，不能单凭该指标确定电音根因。无丢包也不能排除采集端的音频处理异常。浏览器后台节流可能使采样间隔超过 5 秒；实际采样时间随记录导出。

## 实施状态

仅改前端：使用 LiveKit 公开的 getRTCStatsReport/getSourceTrackSettings 接口，不使用私有连接对象。采样不重叠，离房时停止，旧连接的异步结果丢弃。读取失败不打断通话。

保持回退版本的固定原生降噪参数与原有音量处理链；没有增加 AudioWorklet、阈值节点或第二条麦克风采集。处理器仅增加生命周期事件记录。

本阶段未运行构建或真机测试，也未发布到服务器。后续用团队实际通话收集正常/异常双方记录，再实施第二阶段的独立对照版本。
