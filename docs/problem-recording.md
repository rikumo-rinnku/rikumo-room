# 三分钟语音问题记录

管理员或超级管理员进入房间，打开 **通话诊断 → 问题记录 → 开启三分钟缓存**。
房间成员会看到缓存提醒。缓存不足三分钟时仅保存已有内容。

出现问题时选择成员和异常类型，点击 **标记异常**，再点击 **保存最近三分钟**。
下载 ZIP 后解压，使用 Chrome 打开 **回听录音.html**，按成员回听各片段。
`manifest.json` 包含时间、成员、异常标记与缺失说明；另两个 JSON 分别为记录者和各成员诊断。
加速比例、缓冲延迟等新增指标在诊断导出中，不主动改变通话播放行为。

## 实现与限制

- 录音只在开启者浏览器内存中保存，不持续上传语音。目标码率 48 kbps/成员。
- 使用已经发布或订阅的音轨克隆，不重新申请麦克风；不会修改原音轨或发送处理器。
- 本人的轨道是实际发送声音，其他人的轨道是记录者接收到的声音。录音不包含个人收听音量调整，不能代替每位听众的扬声器实际输出。
- 约 30 秒一个完整压缩文件，保留循环窗口；导出时裁掉窗口之前的边界声音。无法裁剪的首片段跳过并明确说明，不拼接可能无法播放的任意压缩分片。
- 一秒维护缓存，三十秒轮换压缩片段，ZIP 在 Worker 中打包。导出首片段会短暂增加解码和内存开销，尚未完成真实设备性能验收。
- 停止/离开/失败/64 MB 上限会清空缓存。页面关闭后缓存不可恢复。浏览器暂停、休眠、网络断开会产生缺失，不能保证录音无间隙。
- 后台仅保存短暂诊断数据，校验真实 LiveKit 房间成员、管理员权限和会话所有者。诊断每五秒上报，开启者三十秒失联后自动释放会话。
- 单房间仅一名记录者。后台为单进程内存状态；API 重启结束会话，刷新后的管理员需要重新开启缓存。
- 所有成员需要刷新至此版本，旧页面不会上报诊断。缺少某成员上报不影响已有录音导出；汇总获取失败时下载包会标明仅有本机诊断。

## 更新

本版同时新增后端会话接口，必须使用完整更新：

```powershell
python deploy/publish.py --host 203.0.113.10 --user root --port 22 --update
```

不重启 LiveKit。账户、房间、密钥和原媒体配置保留。
